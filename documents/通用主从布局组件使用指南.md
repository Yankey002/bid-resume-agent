# 通用主从布局组件 (MasterDetailLayout) 使用指南

## 1. 组件简介

`MasterDetailLayout` 是项目中用于实现**左侧列表、右侧详情**（Master-Detail）模式的标准布局组件。它被广泛应用于“简历库”、“模板中心”和“设置”等模块。

该组件的核心设计目标是：
*   **统一的视觉体验**：确保所有模块的侧边栏交互、宽度和动画一致。
*   **响应式侧边栏**：支持手动展开/折叠，并能将折叠状态传递给子组件。
*   **Header 避让机制**：配合全局的玻璃拟态 Header，提供标准的布局容器。
*   **独立滚动**：将列表区和详情区隔离，互不影响滚动条。

## 2. 组件路径

`frontend/src/components/layout/MasterDetailLayout.tsx`

## 3. Props 定义

| 属性名 | 类型 | 默认值 | 说明 |
| :--- | :--- | :--- | :--- |
| `sidebarContent` | `React.ReactNode` | - | 左侧侧边栏的内容（通常是列表组件，如 `CandidateList`）。组件会自动克隆并注入 `collapsed` 属性给子组件。 |
| `mainContent` | `React.ReactNode` | - | 右侧主要内容区（通常是详情组件，如 `CandidateDetail`）。 |
| `isSidebarOpen` | `boolean` | `true` | 控制侧边栏是否展开。通常由外部 Store（如 `useResumeStore`）管理。 |
| `sidebarWidth` | `number` | `300` | 侧边栏展开时的宽度（像素）。 |
| `collapsedWidth` | `number` | `60` | 侧边栏折叠时的宽度（像素）。 |

## 4. 使用示例

以下是一个典型的使用场景（参考 `ResumeLibrary.tsx`）：

```tsx
import React from 'react';
import { MasterDetailLayout } from '../components/layout/MasterDetailLayout';
import { CandidateList } from '../features/resumes/components/CandidateList';
import { CandidateDetail } from '../features/resumes/components/CandidateDetail';
import useResumeStore from '../store/useResumeStore';

const ResumeLibrary: React.FC = () => {
  // 1. 从全局 Store 获取侧边栏状态（以便 Header 上的按钮也能控制它）
  const isSidebarOpen = useResumeStore((s) => s.isSidebarOpen);

  return (
    <MasterDetailLayout
      // 2. 绑定状态
      isSidebarOpen={isSidebarOpen}

      // 3. 传入左侧列表组件
      // 注意：CandidateList 内部需要处理 collapsed 属性来适配折叠样式
      sidebarContent={
        <CandidateList onSelectCandidate={...} />
      }

      // 4. 传入右侧详情组件
      mainContent={
        <CandidateDetail candidateId={...} />
      }
    />
  );
};
```

## 5. 关键注意事项 (Best Practices)

### 5.1 Header 避让 (Padding Top)

由于全局 Header 采用了 `position: absolute` 和玻璃拟态效果（Glassmorphism），它悬浮在内容之上。因此，**`mainContent` 和 `sidebarContent` 的内部容器必须设置顶部的 `padding`，否则内容会被 Header 遮挡。**

*   **标准顶部间距**：`padding-top: 64px` (Header 高度)。
*   **推荐做法**：在列表组件和详情组件的根 `div` 或滚动容器上设置。

**错误示例**：
```tsx
// ❌ 内容会被 Header 盖住
const MyDetail = () => (
  <div style={{ height: '100%', overflowY: 'auto' }}>
    <h1>标题</h1>
    ...
  </div>
);
```

**正确示例**：
```tsx
// ✅ 内容从 Header 下方开始，且滚动时能穿过 Header 下方
const MyDetail = () => (
  <div style={{
    height: '100%',
    overflowY: 'auto',
    paddingTop: 64, // 关键点：避让 Header
    boxSizing: 'border-box'
  }}>
    <h1>标题</h1>
    ...
  </div>
);
```

### 5.2 独立滚动 (Independent Scrolling)

`MasterDetailLayout` 自身设置了 `overflow: hidden` 来锁定视口高度。你需要确保子组件（列表和详情）自己处理滚动。

*   **侧边栏**：`sidebarContent` 的容器应设置 `overflow-y: auto`。
*   **详情区**：`mainContent` 的容器应设置 `overflow-y: auto`。

这样设计的好处是：当右侧内容很长时，滚动不会影响左侧列表的位置；反之亦然。

### 5.3 侧边栏折叠适配

当 `isSidebarOpen={false}` 时，`MasterDetailLayout` 会将 `collapsed={true}` 属性传递给 `sidebarContent` 的直接子组件。

你的列表组件（如 `TemplateList`）应该接收这个 props 并调整 UI：
*   隐藏文本，只显示图标。
*   居中显示图标。
*   调整 Padding。
*   使用 `Tooltip` 显示被隐藏的文本标题。

### 5.4 状态管理

建议将 `isSidebarOpen` 状态放在 Zustand Store 中，而不是页面的局部 State。
原因：**Header 上的操作按钮**（如“展开/折叠”按钮）通常位于 `HeaderAction` 组件中，它与页面主体是分离的。通过 Store 共享状态，可以轻松实现“在 Header 点击按钮，控制下方 Layout 侧边栏”的交互。
