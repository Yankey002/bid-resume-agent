# 服务器部署说明（通用｜纯子域多站点｜Caddy 统一入口）

域名：`qishirecord.cn`（含 `www.qishirecord.cn`）

站点形态（纯子域）：

- 前端：`https://<site>.qishirecord.cn/`（示例：`qmeta.qishirecord.cn`、`resume.qishirecord.cn`）
- 可选后端：`https://api.<site>.qishirecord.cn/`（示例：`api.qmeta.qishirecord.cn`）

说明：

- 本仓库项目为 `resume`，其前端构建产物部署在 `/srv/www/resume/`
- 文档以“纯子域多站点”骨架为目标，示例中出现的 `qmeta` 仅用于说明多站点能力

目标：

- 单台轻量服务器稳定承载多个“前端 + 后端 + 数据库”站点
- 公网统一入口，只暴露 `80/443`（可选增加 `51820/udp` 用于 WireGuard）
- 自动 TLS（ACME），按子域扩展时不引入“路径/子域混合”配置
- 每个站点独立部署、独立数据目录、独立环境变量，避免互相污染

## 1. 架构概览

核心思想：一个“边界入口”承接公网流量，多站点按子域（SNI）分发；各站点后端与数据库只在 Docker 内网或 WireGuard 专网可达。

- 统一入口：`edge`（Caddy 容器）
  - 对公网监听：`80/443`
  - 负责：自动 TLS、静态站点托管、反向代理、统一健康检查
- 站点目录：`/opt/stacks/<site>/`
  - 每个站点一套 `compose.yml` + `.env`（若该站点包含后端/数据库）
- 静态资源：`/srv/www/<site>/`
  - 只放构建产物（`index.html`、`assets/` 等）
- 数据目录：`/var/lib/<site>/`
  - 数据库卷与持久化数据（按站点隔离）
- 入口状态数据（Caddy）：`/var/lib/edge/caddy/`
  - 证书、ACME 账号、配置缓存等（不要手工清理）
- 遗留归档：`/root/_legacy/`
  - 旧项目与旧容器编排归档，不参与现网运行
- WireGuard（可选）：
  - 服务器作为公网可达端，监听 `51820/udp`
  - 开发机作为对等端，将“后端/数据库”通过 WireGuard 专网暴露给服务器入口

## 2. 闭环验收清单（现网以服务器实际为准）

端口与容器：

```bash
docker ps --format "table {{.Names}}\t{{.Status}}\t{{.Ports}}"
ss -tulnp | egrep ":(80|443)\\b" || true
```

期望状态（骨架搭好后的标准形态）：

- `edge`：对公网 `80/443`
- 其他后端/数据库容器：不对公网映射端口（仅容器内网）

DNS（每个子域必须解析到同一台入口机）：

- `qishirecord.cn`、`www.qishirecord.cn`、`qmeta.qishirecord.cn`、`resume.qishirecord.cn`（以及未来新增的 `<site>.qishirecord.cn`）
- 推荐增加一条 `*.qishirecord.cn` 的 A/AAAA 记录指向入口机（后续新增站点通常无需再改 DNS）
- 如果设置了 CAA，必须允许 `letsencrypt.org`（否则会导致证书长期签发失败）

入口一致性：

- 入口只保留 `edge`（Caddy），不再运行 `edge-nginx` 之类旧入口容器
- 不再需要 `certbot renew` 定时任务（由 Caddy 自动续期）

健康检查与 HTTPS：

```bash
curl -fsS https://qishirecord.cn/health
curl -I http://qmeta.qishirecord.cn
curl -fsS https://qmeta.qishirecord.cn | head
```

## 3. 目录结构（规范）

```text
/opt/stacks/
  edge/
    compose.yml
    caddy/
      Caddyfile
  <site>/        # 仅当该站点包含后端/数据库时才需要
    compose.yml
    .env
  _template/
    app_postgres/
      compose.yml
      .env.example

/srv/www/
  root/         # 主站入口页（站点导航）
  qmeta/        # qmeta 前端构建产物
  resume/       # resume 前端构建产物

/var/lib/
  edge/
    caddy/
      data/      # Caddy 自动证书、ACME 账号等
      config/    # Caddy 配置缓存
  <site>/        # 站点数据（如 postgres / redis 等）

/root/_legacy/
  <any>.YYYYmmdd-HHMMSS/   # 旧栈归档目录
```

## 4. 域名与路由约定（纯子域）

统一约定（推荐）：

- 前端：`https://<site>.qishirecord.cn/`
- 后端：`https://api.<site>.qishirecord.cn/`

当前已配置（示例）：

- `https://qishirecord.cn/`、`https://www.qishirecord.cn/` → `/srv/www/root`
- `https://qmeta.qishirecord.cn/` → `/srv/www/qmeta`
- `https://resume.qishirecord.cn/` → `/srv/www/resume`
- `https://qishirecord.cn/health` → 统一健康检查（返回 `200`）

## 5. 端口策略（生产建议）

对公网开放（推荐）：

- `22/tcp`：SSH 管理
- `80/tcp`：HTTP（自动跳 HTTPS）
- `443/tcp`：HTTPS
- `51820/udp`：WireGuard（可选）

禁止对公网直开：

- `3001/5432/8080` 等业务端口（仅容器内网/服务器回环使用）

## 6. 常用运维命令

统一入口（Caddy）：

```bash
docker network inspect edge >/dev/null 2>&1 || docker network create edge
cd /opt/stacks/edge
docker compose up -d
docker logs --tail 200 edge
docker exec edge caddy validate --config /etc/caddy/Caddyfile
docker exec edge caddy reload --config /etc/caddy/Caddyfile
```

站点（以 qmeta 为例，只有在该站点存在后端/数据库时才需要）：

```bash
cd /opt/stacks/qmeta
docker compose --env-file .env up -d
docker compose --env-file .env logs -f --tail 200
docker compose --env-file .env down
```

## 7. WireGuard：开发机承载后端/数据库（resume 特殊形态）

适用场景：服务器只托管前端与入口；后端与数据库在开发机（Windows/Linux）上运行，通过 WireGuard 与服务器互联，入口再将 `api.<site>` 反代到开发机的 WireGuard 地址。

推荐地址规划（示例）：

- 服务器 `wg0`：`10.8.0.1/24`
- 开发机 `wg0`：`10.8.0.2/32`
- 后端监听：`10.8.0.2:3001`（仅 WireGuard 可达，不对公网开放）

服务器侧（opencloudOS8）：

```bash
dnf install -y wireguard-tools
umask 077
wg genkey | tee /etc/wireguard/server.key | wg pubkey > /etc/wireguard/server.pub
systemctl enable --now wg-quick@wg0
```

`/etc/wireguard/wg0.conf`（示例）：

```ini
[Interface]
Address = 10.8.0.1/24
ListenPort = 51820
PrivateKey = <SERVER_PRIVATE_KEY>

[Peer]
PublicKey = <DEV_PUBLIC_KEY>
AllowedIPs = 10.8.0.2/32
PersistentKeepalive = 25
```

开发机侧（Windows WireGuard 客户端配置示例）：

```ini
[Interface]
Address = 10.8.0.2/32
PrivateKey = <DEV_PRIVATE_KEY>
DNS = 223.5.5.5

[Peer]
PublicKey = <SERVER_PUBLIC_KEY>
Endpoint = 82.156.100.175:51820
AllowedIPs = 10.8.0.1/32
PersistentKeepalive = 25
```

入口反代（Caddyfile 增加 `api.resume` 示例）：

```caddy
api.resume.qishirecord.cn {
  reverse_proxy 10.8.0.2:3001
}
```

连通性验证（在服务器上）：

```bash
wg show
ping -c 3 10.8.0.2
curl -fsS http://10.8.0.2:3001/health || true
```

安全要点：

- 仅开放 `51820/udp` 给公网；业务端口只绑定在 `10.8.0.2` 或仅监听 `127.0.0.1`
- `AllowedIPs` 只允许必要的对端地址（不要设置成 `0.0.0.0/0`）

## 8. 发布前端（以 resume 为例）

将构建产物上传并覆盖到服务器：

- 目录：`/srv/www/resume/`
- 访问：`https://resume.qishirecord.cn/`

注意：

- 因为是独立子域，SPA 构建通常使用默认 base `/` 即可（不再需要 `/resume/` 这类路径 base）
- 如果使用前端路由，入口需确保 `try_files {path} /index.html`（由 Caddyfile 保证）

## 9. 新增第三个网站（标准流程）

目标：新增 `site3`，并保持“纯子域、统一入口、80/443 对外”的一致性。

流程：

1) 准备静态目录

```bash
mkdir -p /srv/www/site3
```

2) 配置 DNS

- 添加 `site3.qishirecord.cn` 的 A/AAAA 记录指向入口机（本机）公网 IP

3) 在 `Caddyfile` 增加站点块并重载

- 文件：`/opt/stacks/edge/caddy/Caddyfile`
- 典型形态：`site3.qishirecord.cn { root * /srv/www/site3 ... }`

4) 如果该站点包含后端/数据库（可选）

- 新建 `/opt/stacks/site3/compose.yml` 与 `.env`
- 确保存在 `edge` 网络：`docker network inspect edge >/dev/null 2>&1 || docker network create edge`
- 确保应用容器加入 `edge` 网络（入口才能反代访问）
- 为后端单独规划子域：`api.site3.qishirecord.cn`（推荐），避免把 API 混到路径里

## 10. 故障排查（最常见）

- `edge` 启动失败且提示端口占用：
  - 说明机器上仍有旧的 nginx/其他服务占用 `80/443`
  - 做法：停止并移除旧入口容器或服务，确保 `80/443` 只被 `edge` 占用
- HTTPS 访问报错或证书迟迟不签发：
  - 常见原因：DNS 未生效/解析错误、存在 CAA 但未允许 `letsencrypt.org`、ACME 速率限制、服务器时间不准
  - 做法：先检查 DNS/CAA，再看 `docker logs --tail 200 edge` 的 ACME 报错信息
- 子域能打开但刷新某个前端路由 404（SPA）：
  - 说明没有对 SPA 做 fallback
  - 做法：在对应站点块启用 `try_files {path} /index.html`
