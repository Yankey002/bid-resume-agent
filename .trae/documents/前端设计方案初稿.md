# 前端设计方案（小而精 MVP，可落地）

目标：开发一个现代化、响应式且“有吸引力”的简历处理工具前端，核心是**流程闭环 + 视觉质感 + 低复杂度**。后端能力通过 RESTful API 对接（Python），前端不承担重解析与重推理。

## 1. 产品定位

- 一句话：批量导入简历 → 提取结构化字段 → 合规检查与可撤销一键优化 → 预览确认 → 导出标准简历/Excel
- 小而精原则：功能做少做深，优先做“稳定闭环”和“用户体验”，避免引入复杂的编辑器/流程引擎

## 2. 范围定义（避免过度复杂化）

### P0（MVP 必做）

- 模板配置：导入 `docx` 模板并管理（只做文件与元信息管理，不做复杂模板编辑器）
- 简历导入与提取：支持多份导入，提取模式支持“模板精准提取 / AI 兜底提取”
- 简历管理：按批次/时间/名称/状态管理，支持标签与筛选
- 审核优化：对 N 份简历运行检查并列出问题；支持对“确定性强”的问题一键优化；优化结果可撤销
- 预览与编辑：预览模式下可编辑结构化字段与关键段落；同时查看图片
- 简历图片：高清查看器（缩放/旋转/裁剪/分类/多图列表）
- 导出：按模板生成标准格式简历（`docx`）或导出结构化 `Excel`；导出记录可追溯

### P1（可选增强，不影响 MVP 交付）

- 图片基础裁剪（轻量）
- 规则包导入/导出（JSON），少量内置规则 + 后端下发规则扩展
- 批量操作增强（批量打标签、批量导出）

### 非目标（明确不做）

- 专业级 `docx` 模板编辑器
- 复杂权限体系/审批流编排/多租户
- 大而全报表与BI
- 专业级图片编辑能力

## 3. 页面信息架构（IA）

- 布局：左侧导航 + 顶部工具栏（全局搜索/导入按钮/任务进度/用户入口）
- 模板中心：模板列表、导入模板、启用/停用
- 简历库：列表（筛选/标签/批次）+ 详情抽屉（字段编辑、原文对照、图片）
- 审核优化：选择集合 → 运行检查 → 问题清单 → 一键优化/逐条处理 → 版本确认
- 导出记录：任务列表、下载入口、关联简历集合
- 设置：提取策略开关、规则包导入/导出、快捷键说明

交互规范：

- 每个按钮必须包含**图标 + 文案**，关键操作提供 Tooltip
- 全局四态：`loading / empty / error / success`；异步任务显示进度并支持取消

## 4. 核心流程（闭环）

1) 导入并入库

- 导入文件 → 选择模板/自动匹配 → 提取 → 校对关键字段 → 入库并打标签

2) 检查并优化

- 在简历库选择 N 份 → 运行检查 → 查看问题 → 一键优化（可撤销）→ 生成“已优化版本”

3) 预览并导出

- 进入预览 → 最后微调 → 选择导出格式 → 生成任务 → 下载 + 记录可追溯

## 5. 视觉与交互（让项目“有吸引力”，但不复杂）

- 主题：默认浅色 + 可选深色（统一色板与阴影层级）
- 质感：卡片式布局、柔和阴影、微动效（hover/press/切换过渡/列表骨架屏）
- 关键反馈：导入/提取/检查/导出都必须有明确进度、成功与失败提示、可重试入口
- 信息密度：列表偏信息密度，详情偏可读性；问题清单支持严重级别颜色标识

## 6. 最小数据模型（前端视角）

- `Template`：`id`、`name`、`fileId`、`updatedAt`、`status`
- `Resume`：`id`、`candidateName`、`batchId`、`templateId`、`tags[]`、`status`、`latestVersionId`
- `ResumeVersion`：`id`、`resumeId`、`source`（extract/manual/optimize）、`fields`、`createdAt`
- `Batch`：`id`、`name`、`createdAt`
- `CheckRule`：`id`、`name`、`severity`、`scope`、`fixable`
- `CheckResult`：`resumeId`、`versionId`、`items[]`（field、message、severity、fixable）
- `ExportJob`：`id`、`type`（docx/excel）、`templateId`、`resumeIds[]`、`status`、`downloadUrl`
- `ImageAsset`：`id`、`resumeId`、`category`、`url`、`meta`

## 7. RESTful API 占位（后端对接契约）

- 模板：`GET /api/templates`、`POST /api/templates/import`、`PATCH /api/templates/{id}`
- 简历：`POST /api/resumes/import`、`GET /api/resumes`、`GET /api/resumes/{id}`、`PATCH /api/resumes/{id}`
- 提取：`POST /api/extract`（批量，返回任务 `jobId`）；`GET /api/jobs/{jobId}`
- 检查/优化：`POST /api/review/check`、`POST /api/review/optimize`
- 导出：`POST /api/export`、`GET /api/export/{id}`
- 图片：`GET /api/resumes/{id}/images`、`PATCH /api/images/{id}`

统一响应约定（建议）：

- 成功：`{ "data": ..., "requestId": "..." }`
- 失败：`{ "error": { "code": "...", "message": "...", "details": ... }, "requestId": "..." }`

## 8. 组件与模块（原子化 + 业务模块化）

基础组件（原子）：

- `Button`、`Input`、`Select`、`Tag`、`Modal`、`Drawer`、`Table`、`Tabs`、`Tooltip`、`Toast`、`Skeleton`

业务组件（模块）：

- 模板：`TemplateList`、`TemplateImportDialog`
- 简历：`ResumeList`、`ResumeDetailDrawer`、`ResumeEditor`、`ResumeRawCompare`
- 审核：`ReviewRunner`、`IssueList`、`IssueDetail`、`OptimizeBar`
- 导出：`ExportDialog`、`ExportJobList`
- 图片：`ImageViewer`、`ImageCategoryPanel`

## 9. 工程与技术（收敛且可扩展）

- 框架：React + TypeScript
- 状态管理：优先轻量（推荐 Zustand）；如使用 Redux，则采用 Redux Toolkit（避免样板代码）
- 样式：CSS Modules + SASS（项目内保持唯一方案）
- API 层：统一封装（超时、错误映射、requestId 透传、任务轮询），与页面逻辑解耦
- 质量：ESLint + TypeScript 严格；关键流程覆盖基础测试（不追求全量）

## 10. 目录结构（建议）

- `src/pages`：页面级路由与组合
- `src/features`：业务模块（template/resume/review/export/image）
- `src/components`：通用组件（原子与通用组合）
- `src/services`：API 请求与 DTO、任务轮询
- `src/store`：全局状态（如选择 Zustand/Redux）
- `src/styles`：主题与全局样式
- `src/utils`：通用工具

## 11. 验收标准（MVP）mi

- 可完成“导入→提取→校对→检查→一键优化（可撤销）→预览→导出→下载记录追溯”的闭环
- 关键异步流程具备进度与可重试，错误提示清晰且不丢上下文
- 列表与详情在 500 份简历量级下交互流畅（分页/虚拟滚动择一）
- 所有按钮都有图标+文案，核心页面支持响应式布局
