# 大模型接入方案实现（12GB 显存｜专业简历处理系统｜Ollama）

本方案目标是在 `12GB` 笔记本 GPU 显存约束下，实现一个可批量、可审计、隐私友好的中文简历处理系统。核心原则：

- 能用规则/解析解决的，优先不用大模型
- 大模型只做“语义理解、冲突解释、建议生成、改写输出”
- 全流程本地处理，不把简历内容发到公网

## 1. 系统分工（落地架构）

建议将处理链路拆成 4 个稳定模块：

1. 文档解析层
   - Word：抽取段落、标题层级、表格、样式（字体/字号/行距）
   - PDF：抽取文本块与布局信息（用于判定“教育/工作/项目”等版块）
2. 规则引擎层（确定性、可审计）
   - 必填字段完整性
   - 日期格式统一与可解析性
   - 时间线基础校验（起止时间、重叠、逆序）
   - 模板/版块结构规范
   - 排版规范（字体/字号/行距等）
3. 大模型层（语义与报告）
   - 技能与工作内容关联性
   - 项目经历与工作经历匹配
   - 自我评价与整体一致性
   - 输出结构化报告 JSON + 可读建议
4. 输出层（修正版与报告）
   - 修正版 Word/PDF：由程序按规则修复格式与替换文案
   - 检查报告：JSON 作为“真源”，再渲染为可读版

## 1.5 公网访问与部署拓扑（国内环境推荐）

目标：在“隐私不出本地 + 成本可控 + 国内网络稳定”的前提下，让公网用户可正常访问前端，并通过轻量服务器间接调用本机大模型推理服务。

结论：优先采用 `WireGuard` 组网把“本机推理服务”私网化，由轻量服务器作为唯一公网入口；隧道类 SaaS（Cloudflare Tunnel/Ngrok）在国内环境存在不确定性，作为备用而非主路径。

### 1.5.1 推荐路径（主路径）：轻量服务器 Nginx + WireGuard 私网回源 + 本机模型

拓扑：

- 浏览器 → `HTTPS` → 轻量服务器（静态站点 + Nginx 反代 + 鉴权/限流）
- 轻量服务器 → `WireGuard` 私网 → 本机（模型/业务 API，仅在 WG 网卡监听）

关键收益：

- 本机服务对公网“不可达”，攻击面收敛到轻量服务器
- 轻量服务器可集中做 TLS、限流、WAF、审计与告警
- 不依赖第三方隧道服务，国内可控性与稳定性更好

### 1.5.2 WireGuard 配置要点（示例）

约定：

- 轻量服务器（公网 IP：`82.156.100.175`）WG 地址：`10.66.66.1/24`
- 本机（家宽/公司网）WG 地址：`10.66.66.2/24`
- 本机模型服务端口示例：`8000`（仅绑定在 `10.66.66.2` 上）

轻量服务器 `/etc/wireguard/wg0.conf`（示例）：

```ini
[Interface]
Address = 10.66.66.1/24
ListenPort = 51820
PrivateKey = <server_private_key>

[Peer]
PublicKey = <laptop_public_key>
AllowedIPs = 10.66.66.2/32
PersistentKeepalive = 25
```

本机 `wg0.conf`（示例）：

```ini
[Interface]
Address = 10.66.66.2/24
PrivateKey = <laptop_private_key>

[Peer]
PublicKey = <server_public_key>
Endpoint = 82.156.100.175:51820
AllowedIPs = 10.66.66.1/32
PersistentKeepalive = 25
```

防火墙最小开放：

- 轻量服务器入站仅开放 `UDP 51820`（WireGuard）与 `TCP 443/80`（Web）
- 本机不需要做任何入站端口映射（只需允许出站访问服务器 `UDP 51820`）

### 1.5.3 Nginx 反向代理要点（示例）

约定前端静态文件部署到轻量服务器（如：`/var/www/app`），模型/业务 API 回源到本机 `10.66.66.2:8000`。

示例（可直接改后落地，证书部分按你实际域名配置）：

- 放在 `http {}` 级别的限流与 WebSocket 变量（示例）：

```nginx
limit_req_zone $binary_remote_addr zone=api_ip:10m rate=5r/s;

map $http_upgrade $connection_upgrade {
  default upgrade;
  ''      close;
}
```

- 站点配置（示例）：

```nginx
server {
  listen 80;
  server_name example.com;
  return 301 https://$host$request_uri;
}

server {
  listen 443 ssl http2;
  server_name example.com;

  root /var/www/app;
  index index.html;

  location / {
    try_files $uri $uri/ /index.html;
  }

  location /api/ {
    limit_req zone=api_ip burst=20 nodelay;

    client_max_body_size 5m;
    proxy_connect_timeout 5s;
    proxy_send_timeout 300s;
    proxy_read_timeout 300s;

    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Request-Id $request_id;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection $connection_upgrade;

    proxy_buffering off;
    proxy_pass http://10.66.66.2:8000;
  }
}
```

- `location /`：静态资源
- `location /api/`：反代到本机私网地址（WG）
- 对 `/api/` 启用限流、超时、请求体大小限制
- 如果走流式输出（SSE/stream），关闭缓冲并提高超时

### 1.5.4 鉴权与风控建议（落地优先级）

1) 轻量服务器对公网：

- `HTTPS`（证书自动续期）
- 频控：按 `IP + userId` 双维度限流，叠加突发限制
- 审计：记录 `requestId、用户标识、耗时、模型名、状态码`，默认不落全文

2) 轻量服务器到本机：

- WireGuard 已提供链路加密与对端认证
- 本机服务仅监听 `10.66.66.2`，避免 `0.0.0.0` 误暴露

3) 应用层（对用户）：

- `JWT` 用于用户会话与权限控制
- 建议增加“额度/配额”机制，避免盗刷造成 GPU 占用与成本外溢

### 1.5.5 备案与域名建议（国内环境现实约束）

- 若使用国内（大陆）云服务器并以自有域名对公网提供站点服务，通常需要 ICP 备案；内测阶段可先使用 `IP:端口` 或海外域名做过渡。

### 1.5.6 备用路径（可选）：FRP 反向代理

当网络环境不稳定、UDP 受限或 WireGuard 不易部署时，可采用 `frps`（部署在轻量服务器）+ `frpc`（部署在本机）建立反向通道，再由 Nginx 回源到服务器本地端口。

取舍：

- 优点：可用 `TCP 443` 等常见端口穿透更顺滑
- 缺点：需要额外维护 FRP 进程与配置，安全与限流仍应落在轻量服务器网关层

### 1.5.7 落地步骤清单（按顺序执行）

- 轻量服务器部署前端静态资源，确认 `https://<域名>` 可访问
- 轻量服务器安装并启用 WireGuard，生成密钥并写入 `/etc/wireguard/wg0.conf`
- 本机安装并启用 WireGuard，确认能 `ping 10.66.66.1` 且服务器能 `ping 10.66.66.2`
- 本机模型/业务服务仅监听 `10.66.66.2:8000`，并提供 `/health` 用于回源健康检查
- 轻量服务器 Nginx 配置 `/api/` 回源 `http://10.66.66.2:8000`，启用限流与超时
- 在轻量服务器实现用户鉴权（JWT）与配额控制，把“防盗刷”前置到网关层

## 2. 模型选型（最适合 12GB 的组合）

### 2.1 推荐默认组合（强烈建议按此开始）

- 主力模型（覆盖 90% 简历，中文+结构化输出稳）：`qwen2.5:7b-instruct`
- 推理增强（时间线冲突/跨段一致性/复杂推导按需）：`deepseek-r1:7b`
- 兜底模型（少量疑难样本，注意缩短上下文）：`qwen2.5:14b-instruct`

理由：在 12GB 下，`7B` 级模型更容易保证吞吐、稳定性与并发余量；“疑难样本”再升级到推理/14B 兜底更划算。

### 2.2 9B 的合理位置（可选增强档）

如果你希望在“主力输出合格但质量一般”的情况下再提升一档，可以加一个 9B 做二级增强（不是默认主力）。例如：

- 二级增强（可选）：`gemma2:9b`

注意：是否能直接拉取、具体 tag 以 `ollama pull` 结果为准。

### 2.3 多模态（可选）

证件照相关需求的“核心判断”仍建议用传统 CV（位置/清晰度/比例/人脸检测）完成；多模态模型只用于把 CV 结果写成自然语言解释。

- 多模态解释（可选）：`llava` 系列或 `qwen2-vl` 系列（以 Ollama 模型库实际可拉取的 tag 为准）

## 3. Ollama 安装与启动

Ollama 支持 Windows/macOS/Linux，可从官网下载安装：`https://ollama.com/`。

安装完成后，确认服务端口（默认）为：`http://localhost:11434`。

## 4. 显存与稳定性配置（Windows PowerShell 可直接用）

### 4.1 PowerShell 会话内生效（推荐用于开发调试）

在 PowerShell 中执行：

```powershell
$env:OLLAMA_MAX_LOADED_MODELS = "1"
$env:OLLAMA_KEEP_ALIVE = "0"
$env:OLLAMA_NUM_PARALLEL = "1"
```

含义：

- `OLLAMA_MAX_LOADED_MODELS=1`：最多同时加载 1 个模型，杜绝多模型挤爆显存
- `OLLAMA_KEEP_ALIVE=0`：请求结束后尽快卸载模型，避免显存常驻
- `OLLAMA_NUM_PARALLEL=1`：限制并行推理，适配笔记本 GPU 稳定性

如果你的 Ollama 版本不支持某个环境变量，通常会被忽略；不影响服务启动。

### 4.2 每次请求的推理参数（建议默认值）

- `num_ctx`：默认 `4096`（疑难样本/14B 兜底可降到 `2048`）
- `temperature`：`0.1`（保证结构化输出稳定、减少编造）

## 5. 拉取模型（以可拉取为准）

推荐先按主力→增强→兜底顺序拉取：

```bash
ollama pull qwen2.5:7b-instruct
ollama pull deepseek-r1:7b
ollama pull qwen2.5:14b-instruct
```

可选 9B：

```bash
ollama pull gemma2:9b
```

验证模型可用：

```bash
ollama run qwen2.5:7b-instruct
```

## 6. 路由策略（不依赖“模型自报置信度”）

不建议使用模型返回的自报 `confidence` 做自动路由，原因是该数值不可校验且漂移大。

推荐使用“可验证信号”触发升级：

- 规则引擎命中 `致命错误`（字段缺失、日期无法解析、格式严重不合规）→ 直接返回，不调用模型
- 主力模型输出无法解析为 JSON / 缺字段 / 不满足 schema → 主力模型重试 1 次（更强 JSON 约束提示）
- 时间线冲突数量 >= 阈值 或 存在跨段矛盾（教育/工作/项目互相打架）→ 走推理增强 `deepseek-r1:7b`
- 推理增强仍无法输出合格结构化 JSON → 走兜底 `qwen2.5:14b-instruct` 并缩短 `num_ctx`

## 7. 结构化输出协议（强制 JSON）

建议所有大模型调用统一输出 schema（JSON 作为“真源”）：

```json
{
  "score": 0,
  "severity": "low | medium | high",
  "format_issues": [
    {
      "code": "MISSING_FIELD | DATE_FORMAT | LAYOUT | TYPO",
      "message": "",
      "location": "",
      "fix": ""
    }
  ],
  "logic_issues": [
    {
      "code": "TIMELINE_CONFLICT | INCONSISTENCY | SKILL_MISMATCH",
      "message": "",
      "evidence": [""],
      "fix": ""
    }
  ],
  "rewrite_suggestions": {
    "summary": "",
    "project_bullets": [""],
    "skill_section": ""
  }
}
```

分数建议由“规则分 + 语义分”组合计算：

- 规则分：确定性扣分（必填字段缺失、日期不合法、结构不合规）
- 语义分：由模型给出，但要附带 `evidence`（证据片段）以便审计

## 8. Ollama HTTP 调用示例（Python 标准库，无额外依赖）

```python
import json
import urllib.request


def ollama_generate(model: str, prompt: str, *, num_ctx: int, temperature: float) -> dict:
    payload = {
        "model": model,
        "prompt": prompt,
        "stream": False,
        "format": "json",
        "options": {
            "num_ctx": num_ctx,
            "temperature": temperature,
        },
    }

    req = urllib.request.Request(
        "http://localhost:11434/api/generate",
        data=json.dumps(payload).encode("utf-8"),
        headers={"Content-Type": "application/json"},
        method="POST",
    )

    with urllib.request.urlopen(req, timeout=120) as resp:
        raw = resp.read().decode("utf-8")
        return json.loads(raw)


def parse_model_json(response: dict) -> dict:
    text = response.get("response", "")
    return json.loads(text)
```

说明：

- `format: "json"` 用于强化“只输出 JSON”约束
- 仍建议做 JSON 解析失败的重试策略（例如重试 1 次，并在 prompt 中强调“只输出 JSON”）

## 9. 最小化隐私暴露（强约束）

- 默认不把原始全文送进模型：传 `结构化摘要 + 关键片段 + 规则结果` 即可
- 对姓名/手机号/邮箱等标识字段做脱敏（在 LLM 输入中使用占位符）
- 所有日志中禁止打印简历原文；只记录任务 ID、规则码、耗时、模型名、版本

## 10. 最终推荐落地配置（可直接照做）

- 模型：`qwen2.5:7b-instruct`（主力） + `deepseek-r1:7b`（按需） + `qwen2.5:14b-instruct`（兜底）
- Ollama：`OLLAMA_MAX_LOADED_MODELS=1`、`OLLAMA_KEEP_ALIVE=0`、`OLLAMA_NUM_PARALLEL=1`
- 推理参数：默认 `num_ctx=4096`、`temperature=0.1`；兜底 `num_ctx=2048`
- 路由：基于规则冲突与结构化输出可验证信号，不用模型自报置信度
